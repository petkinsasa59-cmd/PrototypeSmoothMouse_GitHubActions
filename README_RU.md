# PrototypeSmoothMouse — тестовая версия 0.1

Цель проекта — сделать универсальный фикс мыши для **Prototype 1 (32-bit)**, чтобы пользователю не приходилось менять polling rate мыши, DPI или ставить 60 FPS.

## Важно

Версия 0.1 — **диагностическая база**, а не готовое обещание идеальной камеры. Она перехватывает `IDirectInputDevice8::GetDeviceState`, считает частоту чтения мыши и интервалы между движениями. Это позволит определить, проблема находится в DirectInput или уже в обновлении камеры Prototype.

По умолчанию движение мыши **не сглаживается** (`Smoothing = 0.0`), поэтому первый тест не должен менять ощущение управления. После лога можно будет сделать следующий вариант фикса без гаданий.

## Как собрать без Visual Studio

Нужен только аккаунт GitHub.

1. Создай пустой репозиторий на GitHub, например `PrototypeSmoothMouse`.
2. Распакуй этот архив и загрузи **всё содержимое** в корень репозитория. Обязательно должна сохраниться папка `.github/workflows/`.
3. Открой вкладку **Actions**.
4. Выбери **Build PrototypeSmoothMouse x86**.
5. Нажми **Run workflow**.
6. После завершения сборки открой запущенный workflow и скачай Artifact **PrototypeSmoothMouse-x86**.

GitHub сам соберёт 32-битный `.asi`; Visual Studio на твоём ПК не нужна.

## Установка в Prototype 1

Из Artifact положи рядом с `prototypef.exe`:

- `aaa_PrototypeSmoothMouse.asi`
- `PrototypeSmoothMouse.ini`

Например:

```text
Prototype\
  prototypef.exe
  prototype_fix.asi
  aaa_PrototypeSmoothMouse.asi
  PrototypeSmoothMouse.ini
```

Название начинается с `aaa_`, чтобы ASI Loader постарался загрузить мод как можно раньше, до инициализации DirectInput игрой.

## Первый тест

1. Оставь `Smoothing = 0.0`.
2. Запусти Prototype.
3. Загрузи игру.
4. 5–10 секунд вообще не двигай мышью.
5. Потом 20–30 секунд крути камерой, в том числе в месте, где особенно заметна неплавность.
6. Выйди из игры.
7. Рядом с `prototypef.exe` должен появиться `PrototypeSmoothMouse.log`.
8. Пришли этот лог в чат.

Нас интересуют строки вида:

```text
INPUT state=120.04/s motion=86.11/s avgStateGap=8.33ms maxStateGap=9.10ms avgMotionGap=... maxMotionGap=...
```

Если `state` идёт ровно около частоты игры, но камера всё равно выглядит как 30 FPS — следующий фикс нужно делать уже на уровне **camera interpolation**. Если `GetDeviceState`/motion приходит рывками с большими `max...Gap`, будем исправлять сам путь ввода.

## Экспериментальное сглаживание

Только после первого лога можно попробовать, например:

```ini
Smoothing = 0.35
```

Это распределяет часть большого delta по следующим опросам, сохраняя суммарное движение. Слишком большое значение добавит input lag, поэтому это **не планируется как финальное решение** — это лишь тест.

## Совместимость

Проект собирается как Win32/x86 ASI. Он рассчитан на Prototype 1 и ASI Loader. DXVK может оставаться установленным, но совместимость с другими DirectInput-hook модами ещё нужно проверять тестами.
